## 1. บทนำ

### 1.1 วัตถุประสงค์
ระบบ **SIAM U Connect** เป็นเว็บแอปพลิเคชันสำหรับจัดการข้อมูลนักศึกษา โดยพัฒนาขึ้นใหม่ทั้งหมด (ไม่ใช่การก็อปปี้เว็บเดิม) เพื่อเป็นแพลตฟอร์มกลางที่นักศึกษาเข้าถึงข้อมูลส่วนตัว บัตรนักศึกษา ผลคะแนนกิจกรรม และอันดับผู้เล่นได้จากที่เดียว พร้อมระบบผู้ดูแลระบบที่สามารถจัดการนักศึกษาและมหาวิทยาลัยที่เข้าร่วมได้

### 1.2 ขอบเขต
- ระบบล็อคอินด้วย LINE (โหมดสาธิตสำหรับการนำเสนอ)
- แสดงบัตรนักศึกษา ข้อมูลส่วนตัว GPA จาก API จริง
- แสดงคะแนนกิจกรรม เกม และอันดับ (Leaderboard)
- ระบบผู้ดูแล: เพิ่ม/ลบนักศึกษา, เพิ่ม/ลบมหาวิทยาลัย, ดูรายชื่อมหาวิทยาลัย
- ใช้ API จริงของระบบเดิม (`siam-u-line-welcome-production.up.railway.app`) ผ่าน proxy

### 1.3 กลุ่มผู้ใช้เป้าหมาย
| ผู้ใช้ | บทบาท |
|---|---|
| นักศึกษา | ล็อคอิน LINE → ดูบัตรนักศึกษา, คะแนน, อันดับ |
| ผู้ดูแลระบบ (Admin) | จัดการนักศึกษาและมหาวิทยาลัย |
| ผู้ดูแลระบบระดับสูง (Super Admin) | อนุมัติการเปลี่ยนแปลง (ออกแบบในเฟสถัดไป) |

### 1.4 นิยามศัพท์
| คำ | ความหมาย |
|---|---|
| LINE OAuth | ระบบยืนยันตัวตนผ่านบัญชี LINE |
| IDOR | Insecure Direct Object Reference — ช่องโหว่ที่เข้าถึงข้อมูลผู้อื่นด้วย ID |
| Leaderboard | ตารางอันดับผู้เล่นตามคะแนนรวม |
| GPA | เกรดเฉลี่ยสะสม |

## 2. ภาพรวมของระบบ

### 2.1 สภาพปัญหาเดิม
- เว็บเดิมเป็นระบบเฉพาะมหาวิทยาลัยสยาม ไม่รองรับมหาวิทยาลัยอื่น
- API เปิดเผยข้อมูลส่วนบุคคลโดยไม่ต้องล็อคอิน (พบจาก pentest: `/api/students`, `/api/young`, `/api/export/users`)
- UI/UX เก่า ไม่ทันสมัย ไม่มีระบบผู้ดูแลที่ยืดหยุ่น

### 2.2 แนวทางแก้ไข
1. พัฒนาเว็บใหม่ด้วย **React + Vite** ปรับ UI/UX ให้ทันสมัย (GradientWaves 3D, การ์ดข้อมูล, ธีมมืด)
2. เชื่อม API จริงผ่าน **Vite proxy** พร้อม fallback เมื่อ API ไม่ตอบสนอง
3. เพิ่มระบบผู้ดูแล: จัดการนักศึกษา + มหาวิทยาลัยที่เข้าร่วม
4. ออกแบบด้วยหลักความปลอดภัย (Security by Design) แก้ช่องโหว่ที่พบ

### 2.3 ข้อกำหนดด้านฮาร์ดแวร์/ซอฟต์แวร์
| รายการ | ข้อกำหนด |
|---|---|
| เบราว์เซอร์ | Chrome / Edge / Safari / Firefox เวอร์ชันล่าสุด |
| Node.js | ≥ 18 |
| npm | ≥ 9 |
| ระบบปฏิบัติการ | Windows / macOS / Linux |

## 4. ความต้องการเชิงไม่ฟังก์ชัน

| หมวด | รายละเอียด |
|---|---|
| **ประสิทธิภาพ** | หน้าเว็บโหลดครั้งแรก < 3 วินาที (bundle gzip < 100KB) |
| **ความปลอดภัย** | ข้อมูลส่วนบุคคลต้องไม่รั่วไหล; หน้า admin ต้องตรวจสิทธิ์ทุกครั้ง |
| **ความพร้อมใช้งาน** | ระบบต้องทำงานได้แม้ API หลักล่ม (fallback) |
| **การใช้งาน (Usability)** | รองรับภาษาไทย; UI สอดคล้อง (Responsive); ปุ่ม/สีมีความหมายชัดเจน |
| **การบำรุงรักษา** | โค้ดแยก component ต่อหน้า; มี API layer เดียว (src/api.js) |
| **ความเข้ากันได้** | ทำงานได้ทุกเบราว์เซอร์สมัยใหม่ + จอ mobile |

## 5. สถาปัตยกรรมระบบ

```
┌─────────────────────────────────────────────┐
│               Client (Browser)              │
│  React SPA (Vite) — siam-u-app              │
│  ┌─────────┐ ┌─────────┐ ┌──────────────┐  │
│  │  Pages  │ │ Layout  │ │ GradientWaves│  │
│  └────┬────┘ └────┬────┘ └──────────────┘  │
│       └─────┬─────┘                         │
│         src/api.js (API Layer)              │
└─────────────┬───────────────────────────────┘
              │ /api/* (Vite Dev Proxy)
┌─────────────▼───────────────────────────────┐
│      Backend (Railway — ระบบเดิม)           │
│  https://siam-u-line-welcome-production     │
│  .up.railway.app/api-docs/                  │
└─────────────────────────────────────────────┘
```

**ส่วนประกอบ:**
- **src/api.js** — ชั้นเชื่อมต่อ API เดียว: ดึงข้อมูลจริง → fallback mock
- **src/components/** — GradientWaves (พื้นหลัง 3D), Layout (เมนูด้านข้าง)
- **src/pages/** — LoginPage, Dashboard, StudentCard, Ranking, MyScore, Admin
- **vite.config.js** — proxy `/api/*` → backend จริง

## 7. การออกแบบฐานข้อมูล (ERD)

│ color        │        │ department_name │

       │                │ status          │
       │ 1:N            └─────────────────┘
       ▼
┌──────────────────────────────┐
│  AdminStudent (localStorage) │
├──────────────────────────────┤
│ id (PK)                      │
│ code                         │
│ name / surname               │

│ university → University.name │

┌──────────────────┐      ┌──────────────────┐

**Key หลัก:** `student_code` (รหัสนักศึกษา) ใช้เชื่อมทุกตาราง

## 8. การออกแบบ API

### 8.1 Endpoints ที่ใช้งาน (จาก API จริง)

| Method | Path | ใช้กับ | หมายเหตุ |
|---|---|---|---|
| GET | `/api/students/:code/with-english` | Dashboard, บัตร | ข้อมูลนักศึกษา + ชื่ออังกฤษ |
| GET | `/api/students/:code/id-card` | บัตรนักศึกษา | ข้อมูลบัตร (API จริง 500 → fallback) |
| GET | `/api/game-scores/student/:code` | My Score | ประวัติคะแนนทั้งหมด |
| GET | `/api/game-scores/student/:code/overall-stats` | Dashboard | สถิติรวม |
| GET | `/api/game-scores/student/:code/recent` | My Score | คะแนนล่าสุด |
| GET | `/api/game-scores/leaderboard/:gameType` | Ranking | อันดับ (overall/quiz/...) |

### 8.2 API ใหม่ของระบบ (localStorage)
| ฟังก์ชัน | รายละเอียด |

| `getAdminStudents()` / `addAdminStudent(s)` / `removeAdminStudent(id)` | CRUD นักศึกษาที่ admin เพิ่ม |

## 10. ความปลอดภัยของระบบ

### 10.1 ช่องโหว่ที่พบในระบบเดิม (จาก pentest จริง)
| # | ช่องโหว่ | ความรุนแรง | สถานะ |
|---|---|---|---|
| 1 | ข้อมูลรั่วโดยไม่ต้องล็อคอิน (`/api/students`, `/api/young`) | 🔴 Critical | ระบบใหม่ซ่อน API หลัง proxy + ต้องล็อคอิน |
| 2 | Export ข้อมูลทั้งหมด (`/api/export/users`) | 🔴 Critical | ไม่นำมาใช้ในระบบใหม่; แนะนำปิด |
| 3 | CORS เปิด `*` | 🔴 Critical | ระบบใหม่ใช้ proxy เดียว (ไม่มี CORS เปิด) |
| 4 | SQL Error รั่ว (error disclosure) | 🟠 High | ใช้ generic error ในระบบใหม่ |
| 5 | ไม่มี CSP/HSTS | 🟠 High | วางแผนเพิ่ม security headers |
| 6 | OTP ไม่มี rate limit | 🟡 Medium | ไม่ใช้ OTP ในระบบใหม่ |
| 7 | Swagger เปิดสาธารณะ | 🟡 Medium | จำกัดสิทธิ์ดู API docs |

### 10.2 มาตรการในระบบใหม่
1. **Proxy เดียว** — client ไม่รู้จัก backend จริง (vite proxy)
2. **Role check** — หน้า admin ตรวจ `session.role === 'admin'` ทั้ง render และ logic
3. **Fallback ปลอดภัย** — API ล่มแสดง mock ไม่ใช้ข้อมูลจริงรั่ว
4. **ไม่เก็บข้อมูลอ่อนไหว** — ระบบไม่เก็บ/ส่งข้อมูลบัตรประชาชน

### 10.3 แนวทางอุดช่องโหว่ (Backend MVP กลุ่ม 1)
```js
// 1) JWT Auth + Role Middleware
app.use('/api', requireAuth);
app.use('/api/admin', requireRole('admin'));

// 2) CORS allowlist
app.use(cors({ origin: ['https://siam-frontend-production.up.railway.app'] }));

// 3) Global Error Handler (ซ่อน SQL)
app.use((err, req, res, next) => res.status(500).json({ message: 'Internal server error' }));

// 4) OTP Rate Limiter
app.post('/api/otp/request', rateLimit({ windowMs: 60e3, max: 5 }));

// 5) ปิด Swagger ใน production
if (process.env.NODE_ENV !== 'production') app.use('/api-docs', swaggerUI.serve, ...);
```
